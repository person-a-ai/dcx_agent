## 1. 시작하기

### DCX Agent로 얻는 것

제품 키워드 하나와 문제 정의 한 줄을 넣으면, 네이버 카페에서 소비자 글을 모아 걸러내고 비슷한 이야기끼리 묶은 뒤, 묶음마다 **페르소나(상황 + 인사이트)** 를 돌려준다.

### 접속

브라우저로 서비스 주소에 들어가면 **시작** 화면이 바로 열린다. 로그인은 없다.

### 화면 구성

| 영역 | 역할 |
|---|---|
| 상단 바 | 현재 세션의 `메인 키워드 \| 세션 ID`. 세션이 없으면 "세션 없음" |
| 왼쪽 단계 바 | 8단계 목록과 진행률(예: 3/8). 완료한 단계는 ✓, 지금 단계는 "진행 중". 단계를 누르면 그 화면으로 간다 |
| 가운데 | 지금 단계의 작업 화면 |
| 오른쪽 위 💬 | 파이프라인 챗봇. 지금 단계·키워드 수를 알고 대답한다 |

### 전체 흐름

```
시작 → 키워드 → 크롤링 → 전처리 → 라벨링 → 학습 → 클러스터링 → 페르소나
 1       2        3        4        5        6        7           8
```

크롤링·전처리·학습·클러스터링·페르소나는 서버에서 백그라운드로 돈다. **브라우저를 닫아도 작업은 계속되며**, 다시 열면 마지막 세션이 자동으로 복원된다("세션 복원 중...").

## 2. 단계별 가이드

### 1 · 시작

**목적**: 분석할 주제를 정하고 세션을 만든다.

**이어서 하기**: 위쪽 목록에 저장된 세션이 보인다. 누르면 그 세션이 멈췄던 단계로 바로 이동한다. "삭제"는 확인 창을 거친 뒤 지운다.

**새로 시작** 입력 항목

| 항목 | 필수 | 설명 |
|---|---|---|
| 메인 키워드 | ✅ | 제품·카테고리 이름. 예: `에어컨` |
| 문제정의 | ✅ | 알고 싶은 것을 한두 문장으로. 예: `에어컨 구매 시 소비자 고민 파악` |
| 타겟 | | 주부, 직장인, 1인가구, 신혼부부, 육아맘, 시니어, 대학생, 자영업 (여러 개 선택 가능) |
| 나이대 | | 20대 / 30대 / 40대 / 50대+ |
| 성별 | | 남성 / 여성 |
| 이미 알고 있는 사실 | 권장 | 팀이 이미 아는 사실을 **5~10문장**으로. "＋ 문장 추가"로 칸을 늘린다 |

타겟·나이대·성별은 다음 단계의 키워드 생성에 반영된다.

**"이미 알고 있는 사실"을 적는 이유**: 여기 적은 문장과 비슷한 글은 이후 근거 순위(STEP 09)에서 아래로 내려간다. 적지 않으면 이미 아는 이야기가 "새 근거"처럼 위로 올라온다.
- 0개 · 5개 미만 · 10개 초과일 때는 노란 경고가 뜬다. **막지는 않는다.** 경고를 읽고 그대로 진행해도 된다.
- 같은 문장을 두 번 적으면 하나로 합쳐진다.

**조작**: 입력 → **시작** → 키워드 화면으로 이동.

### 2 · 키워드

**목적**: 크롤링에 쓸 검색 키워드를 Claude와 함께 만든다.

라운드는 네 번 돈다.

| 라운드 | 성격 |
|---|---|
| R1: 발산 | 넓게 뽑는다 |
| R2: 발산 | 한 번 더 넓힌다 |
| R3: 수렴 | 좁힌다 |
| R4: 재발산 | 누적 키워드가 **160개 미만**일 때만 자동으로 추가된다 |

**각 라운드에서 할 일**
1. Claude가 키워드를 카테고리별로 제안한다("키워드 생성 중...").
2. 키워드를 눌러 **승인/거절**을 바꾼다. 기본값은 승인이다.
3. **승인 → 다음**.

**최종 키워드 검토** (라운드가 끝나면 나오는 화면)
- 누르면 승인/거절이 바뀐다. **거절한 키워드는 크롤링에서 빠진다.**
- **전체 승인 / 전체 거절**로 한꺼번에 바꿀 수 있다.
- 카테고리마다 직접 추가(쉼표로 여러 개), **추천 단어 불러오기**(형용사·동사 제안 → "전체 추가"), 드래그로 카테고리 간 이동이 된다.
- 다른 카테고리에 이미 있는 키워드를 넣으면 "이동하시겠습니까?" 카드가 뜬다. **이동** 또는 **무시**를 고른다.
- 카테고리가 10개 이상이면 접힌 상태로 열린다. 위쪽 버튼으로 한 번에 펼치거나 접는다.
- 부족하면 **키워드 더 생성**, 충분하면 **확정 → 크롤링**.

---

### 3 · 크롤링

**목적**: 네이버 카페에서 글을 모은다.

**설정 항목**

| 항목 | 기본값 | 설명 |
|---|---|---|
| 수집 모드 | API만 | **API만**: 빠르다. 제목과 요약만 모은다. **API + 본문 크롤링**: 느리지만 본문, 조회수·댓글·좋아요까지 모은다 |
| 네이버 로그인 쿠키 | (빈칸) | 본문 모드에서만 보인다. 브라우저 개발자도구 → Application → Cookies에서 `NID_AUT`, `NID_SES` 를 `NID_AUT=…; NID_SES=…` 형태로 붙인다. 비우면 일부 카페의 본문을 못 읽는다 |
| 목표 건수 | 50,000 | |
| 시작일 · 종료일 | 최근 1년 | |
| 포함 카페 | (비움 = 전체) | 쉼표로 구분 |
| 제외 카페 | | 예: `중고나라, 번개장터` |
| 광고 필터 | 협찬, 광고, 제공받, 원고료, 체험단, 서포터즈, 중고, 판매, 거래 | 이 단어가 들어간 글은 **수집할 때** 버린다 |

> 쿠키는 개인 로그인 정보다. 공용 PC에서 붙여 넣지 말고, 다른 사람에게 공유하지 않는다.

**크롤링 시작**을 누르면 진행 화면이 나온다.
- 본문 모드는 두 단계로 진행된다. 1단계 API 수집 → 2단계 본문 수집(성공·실패 건수가 함께 표시된다).
- **크롤링 중지**를 누르면 그때까지 모은 데이터는 남는다("중지됨 — N건 수집 완료").
- 끝나면 수집 통계(API 수집 / 본문 성공 / 본문 실패 / 평균 본문 길이), 메타데이터 요약(평균 조회수·댓글·좋아요, 고유 작성자 수, 게시판 분포), 카페별 수집 현황이 보인다.

**전처리 →** 를 눌러 다음 단계로 간다.

---

### 4 · 전처리

**목적**: 중복 글과 내용이 거의 없는 글을 걸러낸다.

자동으로 하는 일
- 같은 링크의 글은 하나만 남긴다.
- 본문이 없고 제목 5자 미만 · 요약 10자 미만인 글은 버린다.

> ⚠️ **알려진 문제**: 지금 버전에서는 "추가 필터" 입력란에 적은 단어가 **적용되지 않는다**. 걸러야 할 단어는 크롤링 단계의 **광고 필터**에 넣는다.

**전처리 시작** → 완료되면 `원본 N → 정제 M건` → **라벨링 →**.

---

### 5 · 라벨링

**목적**: 일부 글에 사람이 "관련/무관"을 붙여, 학습 단계가 나머지 전체를 분류할 기준을 만든다.

- 목표 건수는 정제된 글의 **2%**다. 화면 위에 `목표:N건 | 완료:M건` 으로 표시된다.
- 글마다 **관련**(초록) 또는 **무관**(빨강)을 누른다.
- **저장 후 다음**: 지금 화면의 라벨을 저장하고 새 샘플을 불러온다.
- **완료 → 학습**: 라벨링을 끝낸다.

> ⚠️ **완료 → 학습**은 현재 화면의 라벨을 저장하지 않는다. 마지막 묶음까지 **저장 후 다음**을 누른 뒤 완료한다.

### 6 · 학습

**목적**: 라벨링 결과로 모델을 학습시켜 전체 글을 "관련/무관"으로 자동 분류한다.

- 방식: **3중 준지도 학습 + LLM 앙상블** (LSTM · CNN · GRU · Claude).
- 확신이 낮은 글은 자동으로 확정하지 않고 검수 대상으로 따로 표시한다. 그 기준은 목표 오류율(기본 3%)에서 계산되며, 사람이 직접 정하지 않는다.

**학습 시작** → 진행 중에는 지금 단계가 표시된다 → 완료되면 `전체 · 관련 · 무관` 건수가 나온다 → **클러스터링 →**.

---

### 7 · 클러스터링

**목적**: "관련"으로 분류된 글을 비슷한 이야기끼리 묶는다.

**시작** → 완료되면 클러스터 카드가 나온다(번호, 글 수).

- **체크박스**: 남길 클러스터를 고른다.
- **병합**: 같은 주제의 클러스터 번호를 쉼표로 적는다(예: `1,3,5`).
- **정제 → 페르소나**: 고른 대로 정리하고 다음 단계로 간다.

> ⚠️ **알려진 문제**: 지금 버전에서는 체크박스를 하나라도 고르면 데이터가 모두 빠질 수 있고, 병합은 적용되지 않는다. 수정될 때까지는 **아무것도 고르지 않은 채** **정제 → 페르소나**를 누른다.

---

### 8 · 페르소나

**목적**: 클러스터마다 Claude가 페르소나를 만든다.

**페르소나 도출 시작** → 임베딩과 페르소나 도출이 자동으로 이어진다("Claude 분석중... N%").

완료되면 클러스터마다 카드가 나온다.
- **상황**: 이 묶음의 소비자가 처한 맥락
- **인사이트**: 그 상황에서 드러난 니즈·불편

**처음으로**를 누르면 시작 화면으로 돌아간다.

#### 결과 다시 보기 · 인사이트 화면 (`/insights`)

세션을 고르면 아래 내용을 다시 볼 수 있다.
- 페르소나 분석 결과: 클러스터 이름, 글 수, 주요 키워드, 근거 원문
- **SNA 시각화**: 제품 → 클러스터 → 페르소나 연결망
- 인사이트 챗봇: 결과를 두고 질문한다

## 2-B. DCX 2.0 확장 단계 (STEP 07~11)

> **구현 상태 (2026-10-06)**: STEP 07~11과 관리자 기능은 **백엔드만 완성**됐고 **화면은 아직 없다**(프론트엔드 작업 착수 전). 아래 화면 이름·버튼·열 이름은 승인된 목업 기준이다. 실제 화면이 나오면 문구가 달라질 수 있다. 화면 속 숫자는 예시다.

### 단계 지도: 지금 화면과 DCX 2.0 번호

DCX 2.0은 단계를 00~11 번호로 부른다. 지금 앱의 8개 화면은 그중 08까지에 해당한다.

| 묶음 | 2.0 STEP | 지금 앱 화면 |
|---|---|---|
| Data Defining | 00 세션 · 01·02 입력 선언 | 1 · 시작 |
| | 03 키워드 설계 | 2 · 키워드 |
| | 04 데이터 수집 | 3 · 크롤링 |
| Data Sensing | 05 전처리 · 임베딩 | 4 · 전처리 |
| | 06-A 모델 학습 · 06-B 근거 판정 | 6 · 학습, 5 · 라벨링 |
| | 07 군집 → Touch Point | 7 · 클러스터링 (2.0 화면으로 교체 예정) |
| | 08 페르소나 | 8 · 페르소나 (2.0 화면으로 교체 예정) |
| | 09 근거 수집 | 없음 (신규) |
| Data Shaping | 10-A Customer Action Map | 없음 (신규) |
| | 10-B 기회 영역 | 없음 (신규) |
| | 11-A 인사이트 도출 | 없음 (신규) |
| | 11-B 경험 디자인 컨셉 | 없음 (신규) |
| 운영 | 관리자 · 프롬프트 관리 | 없음 (신규) |

2.0의 핵심 흐름은 이렇다.

```
군집(07) → 페르소나(08) → 행동별 근거(09) → 행동 지도(10-A) → 우선순위(10-B) → 인사이트(11-A) → 컨셉(11-B)
                                                                                  │
                                       다음 세션의 "이미 알고 있는 사실"로 되돌아감 ◀┘
```

### 결과물의 주소: 계층 ID

2.0의 모든 결과물은 위치를 가리키는 ID를 가진다. 어느 화면에서든 이 ID를 따라 원문까지 내려갈 수 있다.

```
CL0 (클러스터) › CL0-P1 (페르소나) › CL0-P1-A1 (행동) › d_000123 (원문)
```

### 06 학습 · 바뀌는 점: 목표 오류율로 검수량 정하기

**상태**: 백엔드 완료 · 화면 목업

지금 학습 화면은 버튼 하나뿐이다. 2.0에서는 학습 전에 **목표 오류율 alpha**를 고른다.

- 선택지: **1% / 3% / 5% / 10%** (기본 3%)
- 고르면 화면에 캘리브레이션 건수(300~500건), 에스컬레이션 건수, **총 검수량**이 보인다.
- 자동 확정과 검수 대기를 가르는 임계값(예: "escalate 임계 0.62")은 alpha에서 **계산되어 표시만 된다**. 사람이 직접 입력하는 칸은 없다.
- 버튼: **[선언 다시 보기]** · **[임계 확정하고 전량 판정]**

**결과**: 글마다 확정(자동/사람)과 **검수 대기**로 나뉜다. 다음 군집 단계에는 **확정된 글만** 들어간다.

> alpha를 낮추면 오류는 줄지만 사람이 검수할 글이 늘어난다. 처음에는 기본값 3%로 시작한다.

### 07 군집 → Touch Point

**상태**: 백엔드 완료 · 화면 목업

**목적**: 비슷한 이야기끼리 묶어 **Touch Point**(고객이 반복해서 겪는 상황)를 찾는다.

**화면에서 보이는 것**
- **실루엣 스코어 그래프**: 클러스터 개수 k를 3~14로 바꿔 가며 묶임이 얼마나 깔끔한지 그린 곡선. 가장 좋은 k가 "채택 k"로 표시된다.
- **Cluster Quality Report**: 진단만 하고, 아무것도 자동으로 바꾸지 않는다.
- **Touch Point 정의**: 클러스터별 대표 어휘와 하위 주제별 대표 원문
- **Cluster 목록** 열

| 열 | 읽는 법 |
|---|---|
| ID | `CL0`, `CL1` … |
| c-TF-IDF 상위 어휘 | 이 클러스터에서 특히 자주 나오는 말 |
| 주된 제약 | 이 상황의 주요 제약 |
| 문서 | 글 수 |
| 밴드 분포 | Core / Fringe / Edge 비율 (아래 규칙 참고) |
| max_sim_to_known | "이미 알고 있는 사실"과 닮은 정도. 높으면 이미 아는 이야기일 가능성이 크다 |
| combo_rarity | 흔한 낱말들이 드물게 조합된 정도. 높으면 새로운 이야기일 가능성이 크다 |
| Persona | 다음 단계에서 붙을 페르소나 |

**조작**: 실행 → 곡선과 목록 확인 → **반례 원문 확인하기 →** 로 Edge 원문을 훑는다 → 페르소나 단계로.

**알아둘 규칙**
- **밴드**는 클러스터 중심에서 떨어진 정도다. **Core**(가까운 50%, 전형적인 글) · **Fringe**(50~90%, 주변 글) · **Edge**(바깥 10%, 반례 후보).
- Edge 글은 **지우지 않는다**. 반례는 뒤 단계에서 근거로 쓰인다.
- 1.0의 Ward 방식은 비교용으로만 함께 돌리고, 클러스터 ID는 임베딩 방식에서만 나온다.
- 시작 단계의 타겟·나이대·성별은 군집에 쓰이지 않는다. 글의 내용만으로 묶는다.

### 08 페르소나 (SNA)

**상태**: 백엔드 완료 · 화면 목업 (지금 앱의 8 · 페르소나 화면은 1.0 방식)

**목적**: 각 클러스터 안에서 **누가 무엇을 원하는지**(Desire·Goal)를 정하고 확정한다.

**화면에서 보이는 것**
- **마이크로 세그먼트 도출 절차**: ① 노드 생성 ② 공출현 빈도 계산 ③ 모듈성 분석(모듈성 Q 값 표시)
- **Eigenvector centrality 상위 16**: 연결망에서 중심이 되는 낱말
- **페르소나 카드**: Persona 명 · Desire(한 문장) · Goal · 소속 Context, 문서 수와 **작성자 수(중복 제거)**
- **Cluster → Persona → Desire 매핑** 표: 문서 · 작성자 · 확정 상태(확정 / 검토 중 / 대기)

**조작**: 카드마다 **[Desire 재생성]** · **[보류]** · **[확정]** 중 하나를 누른다. 오른쪽 대화창에서 확정 진행률(예: 31/48)을 본다.

**결과**: 페르소나 ID(`CL0-P1`)가 생긴다. **여기서 확정한 Desire는 뒤 단계에서 다시 만들지 않는다.** 확정 전에 문장을 충분히 다듬는다.

**알아둘 규칙**
- 페르소나는 반드시 한 클러스터 안에서만 만든다. 클러스터당 2~3개이고, 클러스터를 넘나드는 페르소나는 없다.
- 상황과 페인포인트는 여기서 쓰지 않는다. 10-A에서 근거와 함께 정리한다.
- 작성자 수가 문서 수보다 크게 적으면 소수의 글쓴이가 많이 쓴 것이다. 확정 전에 확인한다.

### 09 근거 수집

**상태**: 백엔드 완료 · 화면 목업

**목적**: 페르소나의 **행동(Action)** 마다 실제 원문 근거를 모은다. 이때 **이미 아는 이야기는 순위를 내리고, 드문 이야기는 올린다.**

**화면에서 보이는 것**
- **Action 도출 · 토픽 맵**: 토픽 모델로 뽑은 행동 후보. λ 슬라이더(기본 0.60)로 대표 어휘의 기준을 조절한다.
- **도출된 Action** 표: ID · Action 문장 · 토픽 비중 · 문서 · 근거 수집 상태(진행 중 / 완료 / 대기)
- **클러스터 중심 문장**: 비교 기준으로만 고정해 두고, 추천 순위에는 넣지 않는다.
- **추천 순위**: **[quality | relevance 단독]** 토글

| 열 | 뜻 |
|---|---|
| relev. | 질문과의 관련도 |
| known ▼ | 이미 아는 사실과 닮은 정도. 닮을수록 감점 |
| rarity ▲ | 조합이 드문 정도. 드물수록 가점 |
| quality | 최종 점수 |
| 순위 이동 | 관련도만으로 줄 세웠을 때보다 몇 칸 올라갔는지(▲)/내려갔는지(▼) |

- **원문 찾기**: 검색 범위를 **이 Context / 이 Persona / 클러스터 / 세션 전체** 중에서 고른다. 필터: 핵심 근거(core) · 보조 단서(supporting) · 반례만 · 밴드 Edge
- **노출 건**: 붙인 근거마다 역할(support 지지 / counter 반례 / rare 희소)과 출처(자동 / 직접)
- **경험차원 커버리지**: 예) 4/6

**조작**: 수집 실행 → 추천 순위 확인 → 원문 찾기에서 좋은 글을 **[붙이기]** → 빼고 싶은 근거는 **[✕]**

**결과**: Action마다 **Evidence Package**(확정된 근거 묶음)가 만들어진다. 10·11단계는 이 묶음만 쓰고 **다시 검색하지 않는다.**

**알아둘 규칙**
- 점수 공식:
  `quality = 관련도 × (1 − 0.5 × 이미 아는 사실과의 유사도) × (1 + 0.3 × 조합 희소성)`
- 시작 단계에서 "이미 알고 있는 사실"을 비워 두면 quality가 관련도와 같아지고 **"감점 항 비활성"** 경고가 뜬다.
- **커버리지 4/6 규칙**: 경험차원 6개(Sense 감각 · Feel 감정 · Think 생각 · Act 행동 · Relate 관계 · Outcome 결과) 중 근거가 붙은 차원이 4개 미만이면 모자란 차원을 자동으로 더 찾는다.
- 검색은 항상 클러스터·페르소나·Context 범위 안에서만 한다. 엉뚱한 클러스터의 글이 섞이지 않게 하기 위해서다.
- 조합 희소성과 경험차원 산식은 아직 **잠정값**이다. 실측 후 바뀔 수 있다.

### 10-A Customer Action Map (CAM)

**상태**: 백엔드 완료 · 화면 목업

**목적**: 행동마다 **상황 → 행동 → 장벽**을 한 열에 정리하고, 각 칸이 근거로 얼마나 뒷받침되는지 **등급**을 붙인다.

**화면에서 보이는 것**
- **페르소나 카드**: Desire · Goal · Pain Points
- **매트릭스**: 열은 행동(A1~A4), 행은 아래와 같다.

| 행 | 내용 |
|---|---|
| 상황 Context | 이 행동이 일어나는 배경 |
| 행동 Action | 실제로 하는 행동 |
| 장벽 Barrier | 원하는 것을 막는 이유 (2.0에서 새로 생긴 행) |
| 키워드 · Artifact | 관련 낱말, 쓰이는 물건·도구 |
| Sentiment | 감정 |
| Opportunity | ODI 점수와 구역 (10-B 참고) |
| 근거 | 근거 건수 · 작성자 수 · 반례 수 |

- 칸마다 **관측 / 추론 / 추측** 배지
- **Action 상세 · Reviews**: 09에서 확정한 근거 원문이 그대로 올라온다. 여기서 다시 검색하지 않는다.
- **등급 기계 판정** 집계: 예) 관측 16/24

**조작**: 서술 생성 → 등급 확인 → **추측 칸 확인하기 →** 를 누르면 09 근거 수집으로 돌아가 근거를 보충할 수 있다.

**등급 규칙** (가장 중요)

| 등급 | 조건 |
|---|---|
| **관측** | 이 행동의 근거 묶음에서 원문이 검색되고, 어휘 겹침이 0.40 이상 |
| **추론** | 원문은 없지만 관측된 다른 칸에서 끌어낼 수 있음 |
| **추측** | 위 둘 다 아님 |

- 등급은 **AI가 스스로 매기지 않는다.** 검색에 걸렸는지라는 사실로만 정한다.
- 추측 칸은 지우지 않고 표시만 한다. **추측 비율이 30%를 넘으면** 그 페르소나의 신뢰도가 **'하'** 로 내려간다.

### 10-B 기회 영역

**상태**: 백엔드 완료 · 화면 목업

**목적**: **중요한데 충족되지 않은** 행동을 찾아 우선순위를 정한다.

**화면에서 보이는 것**
- **Opportunity Map**: 점 하나가 행동 하나, 색은 페르소나
- 구역: **A** Exciting · **B** Experiencing · **C** Competitive · **D** Forsaken · **E** Dangling · **F** At-risk
- ★ 표시: 새로움(novelty)과 ODI가 **둘 다 높은** 행동
- **Action 집계** 표: Importance(중요도) · Satisfaction(만족도) · ODI · 구역 · novelty · 해석
- 경고 배너: "★ 구역 표기는 잠정이다", "⚠ 스케일 경고"

**조작**: 보기 전용 화면이다. 페르소나별 / 전체 보기를 바꿔 가며 본다.

**결과**: 가장 우선순위가 높은 행동이 다음 단계(11-A)의 첫 입력으로 고정된다.

**알아둘 규칙**
- `ODI = 중요도 + max(중요도 − 만족도, 0)`. 중요한데 만족도가 낮을수록 점수가 커진다.
- 만족도는 근거가 **20건 이상**일 때만 계산한다. 그보다 적으면 **"표본 부족"** 으로 표시된다.
- 이 화면은 새로 계산하지 않고 앞 단계 결과를 모아 보여준다.
- 1.0 보고서의 수치와 **직접 비교하지 않는다**(척도가 다르다).
- A~F 구역 경계는 아직 확정되지 않았다. 구역 이름보다 ODI 순위를 먼저 본다.

### 11-A 인사이트 도출

**상태**: 백엔드 완료 · 화면 목업

**목적**: 여러 페르소나에서 나온 행동·장벽을 가로질러 **인사이트**를 종합한다.

**화면에서 보이는 것**
- **‹ Insight 2 / 5 ›**: 인사이트를 하나씩 넘겨 본다. 헤드라인, Pain Point, 기여한 페르소나
- **경험 차원 레이더**(Computed · Connected · Shared). 산식은 아직 미정이다.
- **Opportunity Score**: 평균선이 우선순위 컷 기준
- **인사이트 대화창**

**조작**: 대화창에서 "이 둘을 묶어 줘", "헤드라인을 더 짧게" 같은 요청으로 다듬는다 → **[전송]** → 인사이트를 **확정**한다.

**결과**: **확정한 인사이트는 다음 세션의 "이미 알고 있는 사실"에 자동으로 추가된다.** 그래서 세션을 거듭할수록 같은 이야기는 근거 순위에서 점점 내려가고, 새로운 이야기가 위로 올라온다.

> 확정은 다음 분석의 기준선을 바꾼다. 아직 확신이 없는 인사이트는 확정하지 말고 남겨 둔다.

### 11-B 경험 디자인 컨셉

**상태**: 백엔드 완료 · 화면 목업

**목적**: 인사이트에서 서비스 아이디어를 뽑아 **발표용 컨셉 장표**로 만든다.

**장표 구성**

| 칸 | 내용 |
|---|---|
| 01 PERSONA | 대상 페르소나 |
| 02 SERVICE | 서비스 아이디어. 근거 행동 칩과 ODI |
| 03 EXPERIENCE | 경험 시나리오. 문장마다 **관측** 또는 **추측 · 미래** 배지 |
| 04 INTERVIEW | 검증 인터뷰. 지지/반박, 진행률(예: 인터뷰 2 / 목표 6) |
| 4D-CX | 정신적 · 물리적 · 문화적 · 시스템 세계 비중 |

- **컨셉 목록** 표: ID · 컨셉 · From Insight · 페르소나 · 근거 Action · ODI 합 · 인터뷰 · 4D-CX 주축

**조작**: ‹ › 로 컨셉 이동 → **[인터뷰 슬롯 추가 ＋]** 로 인터뷰 결과 입력 → **[장표로 내보내기]**

**알아둘 규칙**
- 반박 인터뷰가 붙으면 **"컨셉 수정 요청"** 으로 남는다.
- 인터뷰 목표 수에 못 미친 컨셉은 장표에 **"검증 대기"** 로 표시된다.
- 4D-CX 비중은 계산식이 없다. 사람이 판단해 정한다.
- 03 EXPERIENCE의 "추측 · 미래" 문장은 근거가 아니라 제안이다. 발표 때 구분해서 말한다.

### 관리자 · 프롬프트 관리

**상태**: 백엔드 완료 · 화면 목업 · **운영 담당자용**

**목적**: AI 프롬프트와 분석 상수(임계값 등)를 관리한다.

**화면에서 보이는 것**
- **활성 프롬프트 세트**: 예) v7 운영 / v8 초안
- **프롬프트 레지스트리**: 프롬프트 12개. 그중 코드에 박혀 있는 7개는 읽기 전용이다.
- **편집기** · **변수 린트**(빠진 변수 검사)
- **드라이런 대조**: 고정 샘플 20건으로 이전 버전과 결과를 나란히 비교
- **가드레일** · **파이프라인 상수**(잠정 9건)

**조작**: 편집 → 린트 → **[드라이런]** → 결과 비교 → **[활성화]**. 문제가 생기면 **[이전 버전으로 되돌리기]**.

**알아둘 규칙**
- 바꾼 프롬프트는 **다음 세션부터** 적용된다. 진행 중인 세션은 시작할 때의 버전을 끝까지 쓴다.
- 상수를 바꾸면 영향 받는 단계가 **재실행 대기** 상태가 된다.
- "잠정"은 "기본값"이 아니라 **"실측으로 정해질 값"** 이라는 뜻이다.
- 모든 편집은 감사 로그에 남는다.

### 확장 단계의 알려진 제한

- 근거 수집(09)은 벡터 DB 메타데이터 동기화가 끝난 세션에서만 동작한다. 예전 세션은 동기화가 먼저 필요하다.
- 여러 사람이 **동시에** 인사이트를 확정하면 드물게 한쪽 확정이 누락될 수 있다. 확정은 한 사람씩 한다.
- 조합 희소성, 경험차원, 기회 영역 구역 경계는 **잠정 산식**이다. 수치는 상대 비교용으로 보고, 절대값으로 해석하지 않는다.
- 화면 QA(브라우저 검증)는 아직 하지 않았다.

## 3. 용어집

| 용어 | 뜻 |
|---|---|
| 세션 | 분석 한 건. 입력값과 단계별 결과를 모두 담는다. ID는 `s` + 숫자 |

## 4. 자주 묻는 질문

**Q. 브라우저를 닫았더니 진행 중이던 작업이 사라졌나요?**
아니다. 작업은 서버에서 계속 돈다. 다시 열면 마지막 세션이 복원된다. 다른 세션은 시작 화면의 **이어서 하기**에서 고른다.

**Q. 크롤링이 오래 걸려요.**
본문 모드는 글마다 페이지를 연다. 빠르게 보고 싶으면 **API만** 모드로 바꾸거나 목표 건수를 줄인다. 중간에 **크롤링 중지**를 눌러도 모은 데이터는 남는다.

**Q. 본문 실패가 많아요.**
로그인해야 읽을 수 있는 카페가 많기 때문이다. 네이버 로그인 쿠키를 넣고 다시 수집한다.

**Q. 라벨링을 얼마나 해야 하나요?**
화면의 목표(정제된 글의 2%)를 채우는 것이 기준이다. "관련"과 "무관"이 한쪽으로 크게 치우치지 않게 붙인다.

**Q. "이미 알고 있는 사실" 경고가 떴어요.**
경고일 뿐 진행은 된다. 다만 5문장 미만이면 감점이 거의 걸리지 않고, 10문장을 넘으면 새로운 근거까지 밀려날 수 있다.

**Q. 근거 순위 1위가 관련도 1위와 달라요. 오류인가요?**
아니다. 2.0은 일부러 그렇게 만든다. 관련도가 가장 높은 글은 대개 이미 아는 이야기다. "순위 이동" 열에서 얼마나 움직였는지 보고, 관련도 기준 순위가 궁금하면 **[relevance 단독]** 으로 바꿔 비교한다.

**Q. CAM에 "추측"이 많아요.**
그 행동의 근거 묶음에 원문이 부족하다는 뜻이다. **추측 칸 확인하기 →** 로 09 근거 수집에 돌아가 원문을 붙이면 등급이 올라간다. 추측이 30%를 넘으면 페르소나 신뢰도가 '하'가 된다.

**Q. 기회 영역에 "표본 부족"이 떠요.**
만족도를 계산하려면 근거가 20건 이상 필요하다. ODI 대신 중요도와 원문을 직접 보고 판단한다.

**Q. 인사이트를 확정하면 무엇이 바뀌나요?**
다음 세션의 "이미 알고 있는 사실"에 자동으로 추가된다. 그 뒤로는 같은 이야기가 근거 순위에서 내려간다.

**Q. 전에 했던 단계로 돌아가고 싶어요.**
왼쪽 단계 바에서 단계를 누르거나, 화면 위의 `← 이전 단계로` 링크를 누른다.
