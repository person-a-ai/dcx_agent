# T8 · 페르소나 화면 조립

## 변경 파일

- `frontend/src/components/persona/PersonaScreen.tsx`: 전체 맵 우선 진입, 최대 ODI Context 사전 선택과 상세, PersonaList 연결. 카드 순서를 PersonaSummary → CCM·지도 → 8-B/C/D → 구조 트리로 조립. 선택 페르소나 지도 강조 및 선택 Context 열 강조, 트리 expandedId 연결. 페인포인트·근거 수 CCM 셀, 요약 페인포인트 원문 펼침, 전체 맵 표의 대표 페인포인트 열 추가.
- `frontend/src/components/persona/PersonaScreen.test.ts`: 새 조립·상태 테스트 추가, 기존 탭 테스트를 동시 표시 제목·내용 검증으로 변경.
- `frontend/src/components/persona/persona.css`: 기존 내용 뒤에만 추가. 240px 목록, 1280px 이상 표·지도 2:1, 1024px 미만 보조 패널 세로 배치, 768px 미만 단일 열. 기존 토큰만 사용.
- 이 보고서. `finalReview.test.ts`는 변경 없이 통과.

## 구현 결과

- 카드 본문 ds-card는 Pain Points 항목과 지도에만 사용한다. 8-B/C/D는 탭 역할 요소 없이 제목과 세로 구분선으로 동시에 표시한다.
- 이전 카드의 pain_points 필드 누락과 빈 배열을 구분한다. 안내는 기존 PersonaSummary의 R6 문구·근거 탐색 링크를 재사용한다.
- Promise.allSettled의 cards/map/tree/identities 오류를 각각 보존한다. 해당 영역의 다시 불러오기는 그 API만 호출하며, 성공한 다른 영역을 유지한다.
- 목록·Pain Points·비교 표·지도·각 보조 패널·트리에 로딩 자리를 제공한다. 비교 표는 행 이름을 유지하고, 지도는 점 없는 축·구역 면을 먼저 표시한다.
- R7: 카드 status가 failed이면 세 보조 패널 대신 실패 안내 1개와 기존 다시 만들기를 표시한다. 실패 카드의 package_counts도 유지한다.
- 인사이트 도출, stale 재생성 확인·취소, 읽기 전용 제약, 근거 탐색 이동, 카드 재시도, Known Insight 추가 회귀를 유지한다.

## 최종 검증

- `npm --prefix frontend test`: 73개 파일 / 820개 테스트 통과.

## 조정 및 제한

- 소유 범위 밖인 ContextTable.tsx를 수정하지 않기 위해 PersonaScreen.tsx 안에 PersonaContextTable을 두었다. 기존 정렬·행 포커스/호버 강조·카드 열기 동작과 잠정 기회 표시를 유지하며 대표 페인포인트 열을 추가했다.
- finalReview.test.ts에는 이전 탭 의존 단언이 없어 수정하지 않았다.
- backend 파일은 수정하지 않았고 git 쓰기 명령을 실행하지 않았다. 작업 트리의 다른 작업자 변경은 유지했다.
