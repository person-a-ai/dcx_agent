## 1. 요청 요약

- **사용자가 말한 것**: 클러스터링 → 근거 탐색 → 페르소나 화면이 "너무 많이 깨지고 한눈에 잘 안 들어온다". 직접 만든 이미지 시안 9장(현재 화면 4장, 목표 시안 5장)을 바탕으로 어떻게 바꿀 수 있는지 묻는다.
- **분류**: 화면 3개 단계에 걸친 구조 변경이므로 **아키텍처급 작업**으로 다룬다. 기획 → 설계 → 계획 문서를 각각 승인받은 뒤 구현한다.
- **성공 기준(가정, 확인 필요)**: 실제 세션(세라젬_261012_sk v2, 클러스터 7 · 페르소나 21 · Context 114)에서 각 화면이 겹침이나 잘림 없이 그려지고, "어느 Context가 기회인지"와 "이 페르소나가 무엇을 원하고 어디서 막히는지"를 한 화면에서 읽을 수 있다.

## 4. 데이터 확인 결과 (그릴 수 있는가)

- **바로 그릴 수 있음**: Context별 중요도·만족도·ODI·구역·★·반례·문서 수(map), 카드의 Desire·Goal·Context별 상태·감정·장벽·근거 인용·등급, 8-B/8-C/8-D 필드, 클러스터/페르소나/Context 확정값과 c-TF-IDF 키워드·대표 문서(segment), 근거 탐색의 쿼리·커버리지·근거 목록(evidence).
- **페인포인트는 만들어지지만 중간에 버려짐 (1차 수정 대상)**:
  - 근거 탐색 태깅에서 LLM이 문서마다 `pain_point {text, quote}`를 뽑는다. 세라젬_261012_sk v2에서 태깅 2,050건 중 1,843건, 선정 근거 956건 중 950건에 있다.
  - 근거 묶음(`evidence/assemble.py`)이 문서별 태그·polarity·novelty만 넘기고 `pain_point`는 빼서, 페르소나 카드와 화면에 전달되지 않는다.
- **장벽·상태·감정 칸이 키워드 나열로 나옴**: Context 상황이 키워드(dims)에서 왔으면, 카드 생성 코드가 LLM이 다듬은 문장을 원래 키워드 문자열로 덮어쓴다(`persona/cards.py` 192행 부근). 예: CL0-P0-C1 장벽 "청소 비용 1.5W~36W 10분".
- **지금은 없음 (이번 범위에서 제외)**: Context 간 거리 지도(MDS) 좌표, 용어별 "Context 내 빈도 vs 전체 빈도" 집계, 페르소나 대표 이미지, 여정 분포 %.

## 6. 페인포인트 규칙 (B안)

1. **근거 묶음**: 근거마다 태깅 결과의 `pain_point {text, quote}`를 함께 싣는다. 값이 없으면 null로 둔다.
2. **Context 페인포인트**: 카드를 만들 때 Context마다 페인포인트를 1~3개 둔다.
   - 그 Context 근거에 태깅된 페인포인트가 있으면, 비슷한 문장을 묶어 근거 수가 많은 순서로 고른다. 원문 인용과 근거 번호를 유지하고 **관측**으로 표시한다.
   - 근거는 있는데 태깅된 페인포인트가 없으면, 카드 생성 LLM이 그 Context의 근거 인용만 보고 페인포인트를 쓴다. 인용 근거 번호를 반드시 달고 **추론**으로 표시한다.
   - 근거 자체가 없으면 만들지 않고 "근거 부족"으로 표시한다. 근거 없는 페인포인트를 지어내지 않는다.
3. **페르소나 페인포인트**: Context 페인포인트를 모아 페르소나 단위 Pain Points 3~5개를 고른다. 각 항목은 어느 Context에서 왔는지와 근거 수를 함께 보여 준다.
4. **장벽 칸**: 키워드 나열로 덮어쓰지 않는다. 키워드는 LLM 입력 힌트로만 쓰고, 장벽 칸은 문장으로 쓴다. 장벽 문장이 비면 대표 페인포인트 문장으로 채운다. 상태·감정 칸도 키워드로 덮어쓰지 않는다.
5. **인사이트 연동**: 인사이트 도출 프롬프트가 이미 "pain point 인용"을 입력으로 기대하므로, 카드의 페인포인트를 그대로 넘긴다.

## 7. 수용 기준 (B안)

1. 세라젬_261012_sk v2에서 근거 묶음을 다시 만들면, 근거 항목에 `pain_point`가 실린다. 태깅 결과가 있는 근거는 모두 실려 있다.
2. 페르소나 카드를 다시 만들면, 근거가 있는 Context는 모두 페인포인트가 1개 이상 있다. 관측/추론 표시와 근거 번호가 붙어 있고, 근거가 없는 Context만 "근거 부족"이다.
3. 페르소나 21개 모두 상단 Pain Points가 3개 이상 보인다. 단, 근거가 3건 미만인 페르소나는 있는 만큼만 보인다.
4. 장벽·상태·감정 칸에 키워드를 이어 붙인 문자열(예: "청소 비용 1.5W~36W 10분")이 더 이상 나오지 않는다.
5. 근거 태깅 LLM은 다시 호출하지 않는다. 저장된 태깅 결과를 다시 쓴다. 다시 호출하는 LLM은 페르소나 카드 생성뿐이다.
6. Opportunity Map의 점 114개가 한쪽에 몰리지 않는다. 극단값이 있어도 나머지 점이 축 대부분에 퍼지도록 표시 척도를 정하고, 척도 방식을 축에 적는다. 표와 툴팁에는 원래 값을 보여 준다.
7. A~F 구역이 지도 위에 면과 이름으로 표시된다. 점 라벨은 선택·강조한 Context에만 붙어 글자가 겹치지 않는다. 범례는 클러스터 7개 모양만 보여 준다.
8. 왼쪽 목록에서 가장 긴 페르소나 이름도 칸 밖으로 넘치지 않고, 상태 배지와 겹치지 않는다.
9. 페르소나 카드 화면 상단에서 Actor 정의·Desire·Goal·Pain Points를 스크롤 없이 함께 본다. 하단은 Context를 열로 놓고 Action·상태·감정·장벽·페인포인트·Keywords·Artifact·만족도·기회(구역)·근거 수를 행으로 비교한다. 근거 원문 펼치기는 유지한다.
10. 카드 오른쪽 Opportunity Map은 세션 전체 Context를 흐리게, 선택 페르소나 Context를 진하게 표시한다.
11. 구조 트리는 겹치는 선 없이 표시되고 라벨이 잘리지 않는다. 인사이트 기회 순위 막대는 문장과 겹치지 않는다.
12. 1280px 이상과 768px에서 레이아웃이 깨지지 않는다. 키보드 탭 이동과 스크린리더 레이블은 지금 수준 이상이다.
13. 기존 백엔드·프론트엔드 테스트, 린트, 빌드가 통과한다.

## 8. 제외 범위 (이번 실행)

- 6단계 Context 편집 카드, 7단계 근거 선정 화면 재구성
- Context 간 거리 지도(MDS), 용어 빈도 비교 막대, 페르소나 대표 이미지, 여정 분포 %
- 근거 태깅 프롬프트와 재태깅. 이미 저장된 `pain_point`를 쓴다.
- 중요도·만족도·ODI·구역 산식 변경. 화면 표시 척도만 바꾼다.
- 이미 완료된 다른 세션(세라젬 AI 웰니스 모듈러하우스 등)의 자동 재생성. 각 세션은 사용자가 다시 실행할 때 반영된다.

## 9. 위험

- **추론 페인포인트의 신뢰도**: LLM이 채운 페인포인트는 원문에 없는 해석일 수 있다. 근거 번호를 필수로 하고, 인용 번호가 그 Context 근거가 아니면 버리며, 화면에 **추론**으로 구분한다.
- **장벽 문장 변경**: 지금 코드는 "LLM 재작성이 원래 의미를 바꿀 수 있어서" 키워드 원문을 보존하도록 일부러 만들어져 있다. 문장화하면 근거 번호와 등급 검사로 보완한다.
- **재생성 비용과 시간**: 페르소나 카드 생성 LLM을 다시 돌린다(이번 세션 21개, 앞선 실행 기준 약 10분). 근거 태깅은 다시 하지 않는다.
- **인사이트·컨셉 무효화**: 페르소나를 다시 만들면 인사이트와 컨셉이 지워지고 다시 도출해야 한다.
- **표시 척도와 계산값 혼동, 구역 경계 어긋남**: 축을 펴서 보이면 화면 위치와 실제 값이 달라진다. 기준선(`base`)도 같은 변환으로 그리고, 표·툴팁에는 원래 값을 보여 준다.
- **빈 데이터**: 여정·민감도처럼 근거가 없는 칸은 "근거 부족"으로 일관되게 표시한다.
