# 인사이트(8-E) 화면 재구성 · 기획

## 1. 요청 요약

- **사용자가 말한 것**: 페르소나 화면 재구성(PR #34, main 머지 완료) 뒤에도 인사이트 화면은 예전 그대로다. 시안 "8-E 인사이트 도출 > 인사이트별 Pain Point"처럼 바꾸고 싶다.
- **분류**: 인사이트 도출 출력 필드 추가(LLM 프롬프트·스키마), 코드 계산 필드 추가, 화면 구조 변경이 함께 있으므로 **아키텍처급 작업**으로 다룬다.
- **앞선 실행과의 관계**: `stage6-8-visual-redesign` 1차 기획 8절에서 인사이트 화면은 범위 밖이었다. 그 실행의 페인포인트 연결(카드 → 인사이트 입력)은 이미 main에 있다.
- **성공 기준(가정, 확인 필요)**: 실제 세션에서 인사이트 하나를 고르면 "무엇을 말하는 인사이트인지(제목·문장·태그·기여 페르소나)", "어느 경험 차원에 가까운지(레이더)", "어느 Context가 기회인지(Context별 ODI)", "Context들이 어떤 흐름으로 이어지는지(흐름 카드)"를 스크롤 없이 한 화면에서 읽고, 같은 화면에서 채팅으로 고친다.

## 4. 데이터 확인 결과 (그릴 수 있는가)

- **바로 그릴 수 있음**
  - 제목 `title`, `pain_point`, `context_ids`, `known_ki_id` (`backend/app/persona/insights.py` `InsightItem`)
  - 레이더: 인사이트별 `radar.raw` / `radar.percentile` 3축 (`RADAR_AXES`)
  - Context별 ODI: 근거 묶음 `context_evidence[].metrics.odi`. 세션 평균도 계산 가능.
  - 기여 페르소나: `context_ids` → 근거 묶음의 `PersonaBlock`으로 역추적.
  - 반례: Context `flags`의 `counter_context`.
  - 채팅·판 목록·확정·컨셉: 기존 API 그대로.
- **코드로 계산하면 됨 (새 계산 필드)**
  - 흐름 카드의 레이더 축: 그 Context 중심점(centroid)의 축별 값 중 가장 큰 축. 인사이트 레이더와 같은 `radar()`·`embed_axes()`를 Context 하나에 적용.
  - 흐름 카드의 경험 차원(Sense/Feel/Think/Act/Relate/Outcome): 그 Context 근거 `tags` 목록(`evidence/assemble.py` 244행)에서 가장 많이 나온 차원.
  - 레이더 평균 점선: 세션 인사이트 레이더 원값의 축별 평균.
- **지금은 없음 → 도출 LLM이 함께 생성 (사용자 결정)**
  - `headline`(따옴표 제목, 한 줄), `statements`(번호 문장 정확히 2개), `hashtags`(2~4개)
  - `flow`: 흐름 카드 순서와 카드 문장. 각 항목은 그 인사이트 `context_ids` 안의 Context ID여야 하고, 코드가 검사한다.
- **이번 범위에서 제외**: 대표 이미지(페르소나 이미지와 같은 이유로 데이터 없음). 자리는 이니셜·아이콘 자리표시로 둔다.

## 5. 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 화면만 재배치 | LLM 변경 없이 기존 필드로 시안 배치만 따른다. 제목을 따옴표 자리에, `pain_point`를 문장 자리에, 키워드를 해시태그로 쓴다. 흐름 카드는 `context_ids` 순서. | 재도출 없이 바로 보인다. | 시안의 짧고 읽히는 문구가 안 나온다. |
| **B. 도출 출력 확장 + 화면 재구성 (선택)** | 도출 프롬프트·스키마에 `headline`·`statements`·`hashtags`·`flow`를 추가하고, 코드 계산 필드(Context 축·차원·평균)를 더해 시안 구조로 그린다. | 시안과 같은 문구와 흐름을 얻는다. LLM 출력은 코드가 검사한다. | 기존 세션은 인사이트를 다시 도출해야 새 문구가 보인다. 다시 도출하면 확정·컨셉이 초기화된다. |
| C. 문구만 별도 생성 | 기존 인사이트를 두고 "문구 만들기" LLM 호출을 따로 둔다. | 확정·컨셉이 유지된다. | 기능과 상태가 하나 더 늘고, 인사이트를 채팅으로 고치면 문구가 어긋난다. |

**선택**: B (사용자 결정, 아래 6절).

## 6. 사용자 결정 (이번 대화)

1. 따옴표 제목·번호 문장·해시태그는 **도출 때 LLM이 함께 생성**한다.
2. 인사이트는 **한 번에 하나씩** 보여 주고 `< Insight n / N >`으로 넘긴다.
3. 흐름 카드는 **코드 계산 + LLM 문장**: 레이더 축·경험 차원·반례는 코드가, 카드 문장과 순서는 LLM이 낸다.
4. Opportunity Score는 **그 인사이트의 Context별 ODI 막대 + 세션 전체 Context ODI 평균선**. 인사이트끼리 비교하던 기존 막대는 없앤다.
5. **확정은 상단 바**(`Insight n / N` 옆 토글), **컨셉 만들기·컨셉 상세는 채팅 아래** 영역에 둔다.

## 7. 규칙

1. **새 필드 검사**: `statements`가 2개가 아니거나 `flow`에 그 인사이트 `context_ids` 밖의 ID가 있으면 기존 재시도 1회 규칙으로 다시 요청한다. 그래도 실패하면 지금처럼 도출 실패로 처리한다.
2. **흐름 카드 문장**: LLM은 그 Context의 페인포인트·근거 인용만 바탕으로 쓰고 새 원문을 지어내지 않는다(기존 도출 프롬프트 규칙 유지). `flow`는 `context_ids`의 일부여도 되며 최소 min(2, `context_ids` 개수)개, 최대 `context_ids` 개수. Context가 1개면 카드 1개만 그리고 화살표는 없다.
3. **숫자는 코드 소유**: Context 축·차원·ODI·평균은 LLM이 내지 않는다. LLM이 숫자를 내도 버린다(기존 `InsightItem` 방침과 같음).
4. **채팅 수정**: 인사이트 목록 채팅 수정(`edit.v1.md`)도 새 필드를 유지·수정하도록 같은 스키마를 쓴다. 수정 뒤 계산 필드는 `recompute`로 다시 채운다.
5. **예전 데이터 호환**: 새 필드가 없는 기존 인사이트는 화면에서 `headline` 자리에 `title`, `statements` 자리에 `pain_point`, 해시태그는 숨김, 흐름 카드는 `context_ids` 순서 + 그 Context 대표 페인포인트 문장으로 그린다. 그리고 "다시 도출하면 시안 문구가 채워진다"는 안내를 띄운다.
6. **다시 도출**: 기존 세션을 자동으로 다시 도출하지 않는다. 사용자가 다시 실행할 때 반영된다.

## 8. 수용 기준

1. 새로 도출한 인사이트마다 `headline` 1개, `statements` 2개, `hashtags` 2~4개, `flow`가 7절 2번 개수 규칙대로 저장된다. `flow`의 Context ID는 모두 그 인사이트 `context_ids` 안에 있다.
2. 화면은 인사이트 하나만 보여 주고, `<` `>` 버튼과 키보드로 이전·다음 인사이트로 넘긴다. 현재 위치(`Insight n / N`)가 보인다.
3. 헤더에 `Insight n` 배지, 따옴표 제목, 번호 문장 2개, 해시태그, 기여 페르소나 이름(중복 제거)이 보인다. Known Insight와 같으면 그 표시도 유지한다.
4. 레이더는 3축에 이 인사이트 실선과 세션 인사이트 평균 점선을 함께 그리고, 축 이름 아래에 이 인사이트 값을 적는다. 원값·백분위는 툴팁 또는 보조 텍스트로 유지한다.
5. Opportunity Score는 그 인사이트의 Context별 ODI 막대와 세션 Context ODI 평균 점선을 그린다. 막대 라벨은 Context 짧은 번호와 페르소나 이름 축약을 함께 쓰고, 라벨끼리 또는 막대와 겹치지 않는다. ODI가 없는 Context는 "값 없음"으로 표시한다.
6. 흐름 카드는 LLM 순서대로 화살표로 이어지고, 카드마다 문장·페르소나·Context·경험 차원·레이더 축을 보여 준다. 반례 Context 카드는 빨간 테두리와 "반례" 표시를 단다.
7. 채팅은 하단 가로 띠로 두고 추천 질문 칩을 누르면 입력창에 채워진다. 대화 기록 수가 보이고, 판 목록 보기·되돌리기 기능은 유지한다.
8. 확정 토글은 상단 바에 있고 지금과 같은 API로 저장된다. 컨셉 만들기와 컨셉 상세는 채팅 아래에서 그대로 동작한다.
9. 새 필드가 없는 기존 인사이트도 화면이 깨지지 않고 7절 5번 대체 규칙대로 그려진다.
10. 1280px 이상과 768px에서 레이아웃이 깨지지 않는다(768px에서는 레이더·막대가 세로로 쌓인다). 키보드 탭 이동과 스크린리더 레이블은 지금 수준 이상이다.
11. 기존 백엔드·프론트엔드 테스트, 린트, 빌드가 통과한다. 다시 호출하는 LLM은 인사이트 도출(및 채팅 수정)뿐이다.

## 10. 위험

- **재도출 비용과 초기화**: 새 문구를 보려면 인사이트를 다시 도출해야 하고, 확정·컨셉이 초기화된다. 대체 표시와 안내로 완화한다.
- **LLM 출력 실패 증가**: 필드가 늘어 스키마 검사 실패가 늘 수 있다. 재시도 1회와 명확한 오류 문구를 유지한다.
- **Context 축이 한쪽으로 몰림**: Context 하나의 중심점 축값이 비슷하면 모든 카드가 같은 축으로 나올 수 있다. 원값을 툴팁으로 보여 주고, 축 산식은 바꾸지 않는다.
- **경험 차원 동률**: 태그 수가 같으면 Sense→Feel→Think→Act→Relate→Outcome 순서로 고른다. 근거가 없으면 "근거 부족".
- **채팅 수정과 새 필드 어긋남**: 채팅으로 `context_ids`를 바꾸면 `flow`가 맞지 않을 수 있다. 수정 결과도 1번 규칙으로 검사한다.
