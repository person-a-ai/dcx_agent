# 페르소나 Context 비교 표 · 지도 세로 배치 — 기획

## 문제
페르소나 카드 화면에서 Context 비교 표(CCM)와 Opportunity Map이 1280px 이상에서 좌우 2열로 놓인다(`persona.css` `.persona-comparison-layout{grid-template-columns:minmax(0,1fr) minmax(420px,0.8fr)}`). 표가 화면의 절반 남짓만 쓰고, 칸을 누르면 근거 원문이 그 칸(약 140px) 안에서 펼쳐진다. 긴 인용문이 한 줄에 7~8글자씩 끊기고 표가 아래로 길게 늘어나 원문을 읽기 어렵다.

## 결정 (사용자, 2026-10-27)
- **B안: 비교 표를 가로 전체로 쓰고 지도는 표 아래로 내린다.** 원문을 칸 안에서 펼치는 방식은 유지한다.
- 수정량이 작은 B를 먼저 적용하고, 실제 화면에서 여전히 불편하면 A안(오른쪽 패널을 원문 패널로 전환)을 별도 작업으로 검토한다.

## 대안
| 안 | 설명 | 판단 |
|---|---|---|
| A. 오른쪽 칸 전환 | 칸을 누르면 지도 자리에 원문 패널이 열림 | 수정량이 더 큼(상태 끌어올리기 + 패널). 보류 |
| B. 세로 배치 (선택) | 1280px 이상 2열 규칙 제거 → 표 전체 폭, 지도 아래 | CSS 1줄 |
| C. 행 아래 아코디언 | 누른 행 아래 전체 폭으로 원문 | 표가 끊기고 열 대응이 헷갈림. 거절 |

## 수용 기준
- AC1: 1280px 이상 화면에서 Context 비교 표가 본문 폭 전체를 쓰고, Opportunity Map은 표 아래에 놓인다.
- AC2: Context 2개 페르소나 기준, 1440px 화면에서 표 칸 폭이 기존보다 넓다(기존 약 140px → 300px 이상).
- AC3: 칸을 누르면 근거 원문이 기존처럼 펼쳐지고, 지도 선택·강조 연동(열 강조)은 그대로 동작한다.
- AC4: 1279px 이하 동작은 변하지 않는다(이미 1열).
- AC5: 기존 프런트 lint·build·test와 백엔드 테스트 통과.

## 제외 범위
- 원문 표시 방식 변경(A안 패널, 아코디언).
- 지도 단독 화면(`.persona-map-layout`), 8-C 속성의 "근거 원문" 표시.
- 지도 컴포넌트 내부 크기 조정. 단, 전체 폭에서 지도가 지나치게 커지면 설계 단계에서 최대 폭 제한을 검토한다.

## 위험
- 지도가 표 아래로 가서 표가 길면 스크롤해야 지도가 보인다 → 사용자가 수용(원문 가독성 우선).
- 전체 폭 지도가 세로로 너무 커질 수 있음 → 브라우저 QA에서 확인하고 필요하면 최대 폭을 둔다.
